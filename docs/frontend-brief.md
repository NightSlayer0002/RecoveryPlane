# Operator console implementation

Read docs/HTTP-CONTRACT.md first; it is the exact API interface. Build only apps/web files. Do not change root dependencies or backend. Existing React, React Query, lucide-react, Vite are installed. No need to add dependencies.

Create a professional, polished RecoveryPlane console: warm off-white main canvas, dark ink sidebar, teal accent, amber exception indicators, generous spacing, crisp typography, thin borders, editorial dashboard aesthetic. Avoid gradients, purple, fake charts and oversized tiles. Use local system fonts. Responsive from mobile through desktop. Logo can be simple CSS/SVG plane or layers. Brand tagline 'Bring operations back on track.' Sidebar Inbox, Activity, Integrations, Demo lab; workspace and session role at bottom. Header breadcrumb, connection indicator, user avatar. Main inbox heading 'Exception inbox', explanatory subtitle, 'Simulate exception' button. Compact metrics from API, segmented status filter, search, priority/source filters, semantic clickable table with priority dots, source icons, owner, relative age. Row opens case detail using hash routes so links work. Empty/loading/error states, retry buttons.

Case detail shows breadcrumb, status/priority/owner, context key values, exception message, registered recovery action cards/forms, risk confirmation modal with target and inputs, command outcomes and delivery attempts, canonical activity timeline and notes, related cases. Patch success explicitly leaves case open. Unknown outcome shows retry same command. Use expected version and idempotency key. Conflict refreshes data with a clear message. Dismiss uses confirmation. Viewer controls disabled with reason.

Integrations screen cards and detail with callback URL, actions and enable/disable switches, create integration form and one-time secrets dialog, register action form including input JSON Schema editor with validation errors. Settings admin-only. Demo lab explains actual three scenarios with buttons calling API, shows durable vendor state and a compact walkthrough (simulate, open, patch country, retry verification). Activity lists real events. Show concise in-app API setup help using real contract.

GET /api/session after loading saved sessionStorage token; if none show well-designed login/launch page with 'Open demo workspace' default OPERATOR and optional role chooser ADMIN/VIEWER. Check /api/health for demo availability; normal session uses access token input. All requests through typed API client. Session roles as HTTP contract. Poll active data every 5 seconds and on focus; use fetch-based authenticated SSE invalidation if practical. Explicit sign out. No fake data, inert controls, browser alert/confirm, or secrets in URL.

Vite proxy /api and /v1 -> http://127.0.0.1:3000; host 127.0.0.1 port 5173. Root parent will launch. Prefer plain CSS and lucide icons. No external fonts/network dependencies. Use accessible labels/focus states, button disabled during request, modal Escape and focus management. Run `pnpm.cmd --filter @recoveryplane/web build` (escalate permission if needed); report concerns. Parent controls backend and integration checks. Do not spawn agents. Write report docs/frontend-report.md with changed files, verification and concerns. Return concise result.
